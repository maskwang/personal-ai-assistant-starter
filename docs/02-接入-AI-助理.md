# 02 · 接入 AI 助理（MCP）

目标：让支持 MCP 的 AI 客户端能读写你的 vault。核心是接入 **obsidian-mcp**——一个本地 stdio MCP server，把「读笔记 / 建笔记 / 改笔记 / 搜索 / 打标签」暴露成工具。

前置：Node.js ≥ 18（提供 `npx`）。首次运行 `npx` 会联网下载 obsidian-mcp。

## 1. 通用客户端（Claude Desktop / Cursor 等）

在客户端的 MCP 配置文件里加上：

```json
{
  "mcpServers": {
    "mcp-obsidian": {
      "command": "npx",
      "args": ["-y", "obsidian-mcp", "serve", "--vault", "myvault=/ABSOLUTE/PATH/TO/my-assistant/vault"]
    }
  }
}
```

`myvault` 是你给这个 vault 取的名字，AI 调用工具时用它指定 vault；可以配多个 vault，例如再加一个 `work=/path/to/work`。

## 2. DSH / cordis 形式（本机所有 profile 生效）

把 `config/mcp-obsidian.example.yml` 的内容贴进你的 patch 层（例如 `~/.dsh/cordis.patch.yml`），把路径换成真实绝对路径即可。工具会以 `mcp__mcp-obsidian__*` 的形式出现。

## 3. 让助理守则生效

MCP 只提供「手」，`AGENTS.md` 才是「脑」。在客户端里指定工作目录为 `my-assistant/`，或把你的客户端规则文件（`AGENTS.md` / `CLAUDE.md`）指向本仓库的 `AGENTS.md`。

三层配置各司其职：

| 层 | 文件 | 决定什么 |
| :--- | :--- | :--- |
| 能力 | MCP 配置 | 助理能用哪些工具 |
| 行为 | `AGENTS.md` | 助理怎么工作、往哪写、什么必须沉淀 |
| 结构 | `vault/` 目录与模板 | 信息落到哪里 |

## 4. 验证

让助理做三件事，全过就算接通：

1. 「列出我的 vault 有哪些目录」——验证读；
2. 「在收件箱建一条测试笔记，内容 hello」——验证写；
3. 「搜索包含 hello 的笔记，然后删掉它」——验证搜索与删除。

## 5. 安全边界

- MCP 的编辑工具通常是**整篇替换**，写之前先读、带版本号（etag）再写，避免覆盖 Obsidian 里刚做的改动；
- 破坏性操作（删除、移动）默认进回收站，别轻易改成永久删除；
- 密钥类信息写进笔记前先想一遍：这个仓库将来万一变公开会怎样。
